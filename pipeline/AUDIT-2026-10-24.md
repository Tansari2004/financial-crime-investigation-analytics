## Verified defects and changes

1. **Recovered lower-ID files could bypass publication checks.** A file manifest can be created, fail, and finish on retry after a later file has published. If the recovered file has no accepted rows, no new promotion run exists and the prior maximum-file-ID check skipped it. A live PostgreSQL regression reproduced a 100%-rejected recovered file being skipped. Publication now includes every completed file missing row reconciliation, regardless of its ID; its quality failure rolls back without advancing the publication. A documented policy exception then allows the recovered file to reconcile.
2. **The verifier could pass without complete evidence.** Deleting either reconciliation table, or ingesting a correction without promoting it, previously left a passing report. Verification now checks required file/currency coverage, pending correction IDs and incomplete correction manifests. New tests reproduce each case. The independent dbt amount test also checks missing and unexpected groups instead of accepting an empty table as balanced.
3. **Some Python-valid amounts could not be promoted by PostgreSQL.** Full-width and Arabic-Indic digits were accepted by `Decimal` but rejected by PostgreSQL `numeric`. The input contract now quarantines non-ASCII numeric strings before promotion; valid neighbouring rows can still proceed.
4. **Review and setup details.** The verifier now shares the pipeline's default local connection. The CSV parser docstring now matches its existing malformed-line quarantine behaviour. CI discovers every `test_banking_*.py` file, including new regressions, and watches the benchmark script.
